MISION SISTEMA SOLAR — INSTRUCCIONES PARA PUBLICAR EN GITHUB PAGES

ARCHIVO PRINCIPAL
- index.html: juego web en un solo archivo. No requiere instalar dependencias.

PASOS
1. Entra en https://github.com e inicia sesión (crea una cuenta si aún no tienes una).
2. Pulsa el signo + de la parte superior derecha y selecciona New repository.
3. Escribe como nombre: mision-sistema-solar-ibe
4. Selecciona Public y activa Add a README file. Pulsa Create repository.
5. Dentro del repositorio, pulsa Add file > Upload files.
6. Sube index.html. Puedes subir también este README como documentación, aunque no es necesario para que el juego funcione.
7. Pulsa Commit changes.
8. En el repositorio, entra a Settings > Pages.
9. En Build and deployment, en Source selecciona Deploy from a branch.
10. En Branch, elige main y la carpeta /(root), luego pulsa Save.
11. Espera a que GitHub publique la página. En Settings > Pages aparecerá el enlace Visit site. El enlace suele ser de la forma:
    https://TU-USUARIO.github.io/mision-sistema-solar-ibe/
    Sustituye TU-USUARIO por tu nombre de usuario real de GitHub.
12. Abre el enlace y prueba el juego. El audio utiliza la síntesis de voz disponible en el navegador.

IMPORTANTE
- La publicación GitHub Pages en una cuenta gratuita debe considerarse pública. No incluyas nombres, diagnósticos ni otros datos identificables de niños reales.
- El progreso y los registros se guardan localmente en el navegador usado. El CSV/JSON sirve para exportar manualmente los resultados; no se envían a una base de datos.
- Para que otra persona juegue, comparte el enlace publicado. Si también quieres conservar los resultados de cada jugador, tendrá que descargar su CSV y enviártelo por el medio que acuerden.
- Durante línea base, pruebas derivadas, identidad, categorías de prueba, prueba de sistema solar, generalización y mantenimiento el juego no indica si la respuesta fue correcta.
- La fase de mantenimiento se recomienda aproximadamente una semana después de la finalización, sin entrenamiento adicional. El juego no genera recordatorios automáticos.
- Es un prototipo educativo, no una evaluación clínica validada. La fase de generalización cambia la ilustración vectorial generada por el juego; para evaluar generalización con rigor en participantes reales, deben incorporarse ejemplares visuales nuevos y consultar al docente.
